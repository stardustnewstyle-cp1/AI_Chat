# 学習まとめ（評価者向け・アピール強め版）

## ■ 1. 技術質問を構造的に理解するための分類技術を習得  
Intent 判定の実装を通じて、技術質問を正確に理解するための分類観点とロジックを体系的に学んだ。  
質問文を「比較・設計・手順・改善・要約」などの構造に分解することで、回答精度が大きく向上することを理解し、実装例を参照しながら分類ロジックを自力で構築できるようになった。

→ **質問を構造化して捉える“技術的読解力”が身についた。**

---

## ■ 2. 推論テンプレート設計（ReasoningLayer）を通じて回答生成の基盤を構築  
抽出した Intent と辞書をベースに、推論タイプを数値化して判定する仕組みを実装した。  
既存モデルの考え方を取り入れつつ、回答に必要な情報を整形するためのテンプレート設計を行い、  
「回答の型を先に決める」という実務的なアプローチを理解した。

→ **LLM に依存しない“再現性の高い回答生成基盤”を構築できるようになった。**

---

## ■ 3. 特徴量抽出・レベル判定（ML）でテキストをデータとして扱う力を習得  
質問文を数値化し、既存モデルを参考にレベル（初級・中級・上級）を推定するロジックを実装した。  
特徴量抽出・分類基準の設計・モデルへの入力形式の整合性など、機械学習の基礎工程を一通り経験し、  
ML を「複雑なモデル」ではなく「ルール設計」として扱う視点を身につけた。

→ **テキストを“データ化して判断する”機械学習の基礎を実務レベルで理解した。**

---

## ■ 4. TeacherLayer による構造化回答生成の設計力を習得  
LLM 単体では汎用性に限界があるため、回答の構造（header / content / list / steps / code）を先に決めてから LLM に埋め込ませる設計を学んだ。  
サンプルデータを事前に用意し、整合性を保ちながら回答文を生成することで、  
LLM の出力を安定させるための前処理の重要性を理解した。

→ **LLM を“構造化された枠を埋めるエンジン”として扱う高度な設計力を習得した。**

---

## ■ 5. LLM 連携の実務的理解  
LLM を多層パイプラインの一部として扱うことで、  
「LLM に丸投げしない」実務的な AI 設計を学んだ。

- プロンプト設計の重要性  
- LLM の役割を限定することで回答精度が向上すること  
- 多層構造の中で LLM をどう位置づけるかの理解  

→ **LLM を“使いこなす側”の視点を獲得した。**

---

## ■ 6. FastAPI・UI 連携でアプリとして成立させる力を習得  
バックエンド（多層 AI パイプライン）とフロントエンド（Copilot 風 UI）を連携させ、  
ユーザーが実際に使えるアプリとして成立させるところまで実装した。

- API 設計の基礎  
- バックエンドと UI の連携ポイントの理解  
- Intent 判定・推論構造・レベル判定・セクション構造を UI に反映  
- 非技術質問のフィルタリングと警告カード表示  

→ **“モデルを作るだけ”ではなく“ユーザーが使えるプロダクトとして完成させる力”を習得した。**

---

## ■ 7. 品質設計・例外処理の重要性を理解  
多層構造の連携では、機能の順番やつなぎ方が回答精度に直結することを学んだ。

- 各レイヤーの連携順序が精度に影響することを理解  
- ローカル AI は学習データの質が回答精度に直結することを理解  
- 例外処理・フォールバック設計によりアプリが落ちない構造を実装  

→ **“安定して動く AI システム”を作るための品質設計の基礎を習得した。**

---

## ■ 8. 機械学習の実装を一連の流れで理解  
学習データの抽出 → 整形 → 分類 → モデルへの入力 → 推論 → 出力整形  
という機械学習の基本工程を自力で組み立てられるようになった。

- 特徴量抽出の重要性  
- モデルの入力形式・出力形式の整合性  
- 推論結果を次のレイヤーに渡すための整形処理  
- 推論が不安定な場合の例外処理  

→ **機械学習を“システムの一部として扱う力”を獲得した。**
